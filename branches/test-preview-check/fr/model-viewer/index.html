Structure des éléments

Comment lire ce tableau

Ceci est la structure telle qu'elle est actuellement définie et publiée, avec quelques adaptations pour la lisibilité.

Arborescence
La première ligne est le modèle lui-même. Les lignes en retrait sous une autre ligne sont les composants de ce groupe ; le triangle replie ou déplie un groupe. Tout déplier / Tout replier agissent sur tous les groupes.
Élément
Le nom de l'élément de données. Survolez-le pour lire la définition complète ; la colonne Description montre le texte court.
Card.
Cardinalité, min..max : combien de fois l'élément peut apparaître. 0..1 facultatif, 1..1 obligatoire, 0..* un nombre quelconque, 1..* au moins un.
Type
Le type de données. BackboneElement est un groupe avec ses propres lignes en dessous ; Reference(X) renvoie à un autre modèle.
Glossaire
Le terme du glossaire auquel l'élément est mappé, lorsqu'il existe ; il renvoie au glossaire.
Binding
Pour les éléments codés : la force (required, extensible, preferred, example) et le ValueSet d'où viennent les codes, avec un lien vers sa page dans la version FHIR pour laquelle le modèle est exprimé.

Chaque boîte est un concept : le modèle, et chaque groupe qu'il contient. Les attributs sont les éléments de données avec leur type et leur cardinalité. Un losange plein est une composition, annotée du nombre de parties qu'un tout peut contenir ; une flèche simple est une référence vers un autre modèle ; une pointe creuse désigne le modèle parent.




  


  

    


  
  







Le modèle est la boîte ambre au centre ; chacun de ses éléments est une boîte autour, bleue pour une donnée, grise pour une référence vers un autre modèle, ambre pour un groupe dont les éléments propres sont plus à l'extérieur et pointent vers lui. La flèche pointillée d'un élément vers son concept porte la cardinalité : rouge si l'élément est obligatoire, verte s'il est facultatif. Une boîte verte est le ValueSet auquel un élément est lié. Survolez une boîte pour la description de l'élément.
